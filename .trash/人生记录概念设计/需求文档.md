# **LifeLoop - 个人生活管理系统需求文档**

**版本**: 1.0
**最后更新**: 2023-10-26
**作者**: AI Assistant & You
**状态**: 草案

## **1. 项目愿景与概述**

**项目名称**: LifeLoop
**愿景**: 打造一个极致私密、高度定制化的个人生活管理系统，帮助用户通过便捷记录、结构化复盘和智能分析，形成“记录-反思-成长”的正向循环，最终实现持续的自我优化。
**目标用户**: 注重个人成长、有自我复盘习惯、对数据敏感且高度关注隐私的个体用户。
**核心价值**:
1.  **一体化**: 整合零散的日记、习惯追踪、健康数据于一处。
2.  **自动化**: 最小化记录阻力，最大化自动采集与智能分析。
3.  **仪式化**: 通过内置的、不可跳过的工作流（如每周复盘），培养良好习惯。
4.  **隐私优先**: 所有数据本地存储，AI 分析需经用户手动授权与过滤。

## **2. 功能需求详情**

### **2.1. 核心记录功能 (FR 1)**

| 功能 ID | 功能名称 | 描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR 1.1** | **快速日常记录** | 用户可随时通过主屏幕 FAB 快速创建一条记录。支持纯文本输入。系统自动附加不可修改的创建时间戳。 | 高 |
| **FR 1.2** | **标签系统** | 在创建/编辑记录时，用户可为记录添加一个或多个自定义标签（如 `#灵感`, `#烦恼`, `#工作`）。 | 高 |
| **FR 1.3** | **详情/评论** | 每条主记录下，用户可后续添加多条额外的评论或详情，用于补充记录，形成层级结构。 | 中 |
| **FR 1.4** | **私密标记** | 用户可将任何记录标记为“私密”。被标记的记录在后续的 AI 导出环节中会被默认排除。 | 高 |

### **2.2. 睡眠记录模块 (FR 2)**

| 功能 ID | 功能名称 | 描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR 2.1** | **手动记录** | 用户可通过表单输入睡眠的开始时间和结束时间。系统自动计算并显示总睡眠时长。 | 高 |
| **FR 2.2** | **计时器记录** | 用户点击“开始睡眠”按钮，系统记录开始时间并开始计时。用户醒来后点击“结束睡眠”按钮，系统记录结束时间并停止计时。应用需支持后台计时。 | 高 |
| **FR 2.3** | **睡眠历史视图** | 在一个专属页面，以列表或日历形式展示所有的历史睡眠记录。 | 中 |

### **2.3. 周期性活动模块 (FR 3)**

| 功能 ID | 功能名称 | 描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR 3.1** | **结构化输入** | 提供表单化输入界面，包含：活动类型（下拉选择或自定义）、日期、数值（如次数、组数、重量等）。 | 高 |
| **FR 3.2** | **活动类型管理** | 用户可管理（增删改）一套常用的活动类型（如“俯卧撑”、“跑步”、“阅读”）。 | 中 |
| **FR 3.3** | **统计仪表盘** | 提供简单的统计图表（如折线图、柱状图），按周/月展示特定活动的趋势和总量。 | 中 |

### **2.4. 智能关联系统 (FR 4)**

| 功能 ID | 功能名称 | 描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR 4.1** | **人物提及解析** | 系统在用户保存记录时，自动解析内容，识别 `@+人名`（如 `@张三`）格式的文本。 | 高 |
| **FR 4.2** | **人物实体管理** | 自动为每个被提及的唯一人名创建一个独立的“人物”实体。 | 高 |
| **FR 4.3** | **人物详情页** | 点击任一人物实体，进入其详情页，该页面动态聚合并展示了所有提及此人的记录。 | 高 |

### **2.5. 复盘系统 (FR 5)**

| 功能 ID | 功能名称 | 描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR 5.1** | **每周复盘界面** | 每周六，应用在首页或复盘页提供明显的入口，引导用户进行复盘。 | 高 |
| **FR 5.2** | **本周记录回顾** | 复盘界面的一部分，自动列出本周的所有记录，并提供简单的工具（如复选框或表情符号）让用户标记“成就”或“不足”。 | 高 |
| **FR 5.3** | **混乱度检查清单** | 复盘界面的另一部分，提供一个固定的、不可修改的检查清单（项目：桌面整洁、个人卫生、早睡等），用户需逐项勾选确认完成。 | 高 |
| **FR 5.4** | **月度数据导出** | 每月底，用户可手动触发“月度导出”功能。系统准备本月的所有数据。 | 高 |
| **FR 5.5** | **隐私过滤与 AI 集成** | 在导出前，系统**必须**明确提示用户，并提供选项自动过滤掉所有标记为“私密”的记录。导出后，提供“复制到剪贴板”按钮，方便用户粘贴到外部 AI 工具。**不直接集成 AI API**。 | 高 |

### **2.6. 数据管理与统计 (FR 6)**

| 功能 ID | 功能名称 | 描述 | 优先级 |
| :--- | :--- | :--- | :--- |
| **FR 6.1** | **本地数据存储** | 所有数据必须存储在用户设备本地，无需网络权限。 | 必须 |
| **FR 6.2** | **数据备份与恢复** | 提供将全部数据导出为单一文件（如 JSON 或 ZIP），并可从该文件恢复的功能。 | 高 |
| **FR 6.3** | **图表可视化** | 在统计页面，为睡眠时长、活动频率等量化数据提供简单的趋势图表。 | 中 |

## **3. 非功能需求**

1.  **性能**:
    *   应用启动时间应小于 2 秒。
    *   所有操作（增删改查）应感觉流畅，无明显卡顿。
2.  **可用性**:
    *   界面简洁直观，核心操作（添加记录）应在 3 次点击内完成。
    *   遵循 Material Design 3 设计规范，提供熟悉的用户体验。
3.  **可靠性**:
    *   应用崩溃率应低于 1%。
    *   数据必须保证完整性，避免因意外崩溃导致数据丢失。
4.  **安全性 & 隐私**:
    *   **绝不收集任何用户数据**。
    *   所有数据存储在设备本地。
    *   为支持备份功能，申请的外部存储权限需向用户清晰解释。
5.  **兼容性**:
    *   支持 Android SDK 24+ (Android 7.0) 和 iOS 13+。

## **4. 数据模型 (核心)**

*   **DailyLog**: `{id, content, timestamp, tags: [], isPrivate: bool, mentionedPersonIds: []}`
*   **SleepRecord**: `{id, startTime, endTime}`
*   **WorkoutRecord**: `{id, date, type, sets, reps, ...}`
*   **Person**: `{id, name}`

## **5. 后续版本考量 (V 2.0+)**

1.  **自定义复盘模板**: 允许用户自定义“混乱度检查”的清单内容。
2.  **高级图表分析**: 提供更复杂的数据关联分析（如“睡眠质量与健身表现的关系”）。
3.  **Web 端支持**: 基于同一套数据同步方案，开发 Web 客户端。
4.  **端到端加密同步**: 在用户完全掌控的前提下，提供跨设备加密同步方案（如通过 Syncthing 或自建 WebDAV）。
