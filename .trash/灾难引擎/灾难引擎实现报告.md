# 多模态灾情数据处理中心技术原型设计报告

## 一、系统核心架构

### 精简系统架构图
```
[仿真数据源] → [STGNN预测引擎] ↘ 
                         [地图数据中心] → [存储系统]
[文本数据流] → [DeepSeek分析引擎] ↗
```

---

## 二、核心模块设计

### 1. 数据输入模块
- **仿真数据源**：
  - 模拟时间控制器（按时间序列生成数据）
  - 支持加速/暂停/重置模拟
  - 数据分发队列管理

- **文本输入接口**：
  ```json
  {
    "timestamp": "2023-10-01T12:00:00",
    "id":"风雨哥",
    "location": "花都区",
    "content": "这么大的雨，学校都停课咯"
  }
  ```

### 2. 处理引擎
| 引擎类型          | 输入               | 输出                           | 实现方案            |
| ------------- | ---------------- | ---------------------------- | --------------- |
| STGNN 预测引擎    | 气象时序数据<br>静态地理数据 | 网格化风险指数<br>(0.0-1.0)         | 时空图神经网络         |
| DeepSeek 分析引擎 | 带时空信息的文本         | 危机指数 (0-100)<br>损失指数 (0-100) | DeepSeek API 封装 |

### 3. 地图数据中心
- **维护三张核心地图**：
  1. STGNN 风险预测图
  2. 文本危机指数图
  3. 文本损失指数图
  （暂时使用成都市区名称简化地图实现）
- **数据更新机制**：
  - 实时接收引擎输出
  - 空间坐标匹配
  - 时间窗口对齐

### 4. 存储系统
- **每小时快照**：
  - 存储格式：JSON
  - 命名规则：YYYYMMDD_HH. json

---

## 三、关键数据流

### 处理流程
1. 仿真系统生成时序数据
2. 双引擎并行处理：
   - STGNN 处理气象/地理数据
   - DeepSeek 分析文本报告
1. 结果写入地图数据中心
2. 整点触发存储任务

### 数据融合示例
```
当收到文本报告时：
  1. 解析地理位置 → 花都区
  2.了解历史预测数据
  2. 调用DeepSeek API → {危机:85, 损失:70}
  3. 更新文本危机/损失地图对应位置
```

---

## 四、原型技术方案

### STGNN 预测引擎
- **输入处理**：
  - 气象数据标准化
  - 地理数据网格化
- **输出处理**：
  - 风险值归一化 (0.0-1.0)
  - 附加时空坐标信息

### DeepSeek 集成方案
```python
目前使用deepseek开放平台api
后续考虑使用微调的本地模型进一步提高响应速度
输出两个风险数据
```

### 地图数据维护
```python
使用一个抽象的储存类
维护地理数据表结构
```

## 五、存储方案

由储存类内部方法存储，目前采用json 文件的方式逐小时存储。项目架构分层设计，故可以方便切换为数据库实现
