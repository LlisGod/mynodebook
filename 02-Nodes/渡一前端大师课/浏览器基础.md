# 事件循环

## 浏览器的进程模型
### 进程是什么？
每个程序运行在一个进程里
进程间隔离
可以在条件允许的情况下通信

### 何为线程
线程运行在进程里
每个进程有一个主线程，主线程和线程同生命周期

进程可以同时开启多个线程，同时处理多个任务

进程之间可以互相通信


### 浏览器有那些进程和线程

**浏览器是一个多进程和多线程的应用程序**

浏览器及其复杂，为了防止连环崩坏

主要有
- 浏览器进程
	- 主要负责界面展示，标签页，导航栏，用户交互等等浏览器本身功能
- 网络进程
	- 负责加载网络资源，有多个线程处理网络请求
- 渲染进程
	- **一个标签页一个渲染进程**
		- 谷歌想改变发展为一个站点一个进程
	- 渲染主线程：执行 html，css，js
	- 

## 渲染主线程是如何工作的？
渲染主线程是最忙碌的线程，必须一个任务完成才能进行下一个任务
- 解析 html，Css，计算样式，布局，处理图层，执行事件函数，60 帧刷新......


引入调度难题，比如同步触发，中断触发，计时器回调

使用消息队列处理事务

进入无限循环->检查消息队列是否有任务->调取任务->处理完任务->获取新事件

## 细节

### 何为异步

有许多任务是无法立即执行的
- 计时任务--settimeout
- 网络通信任务
- 用户操作任务

因此用到异步策略

对于不能一次搞定的任务，主线程把    任务交给其他专门的线程执行，结束当前任务
其他线程完成任务后在消息队列中注册新任务，继续后续操作

这样就保证了浏览器永不阻塞

> [!note] 如何理解 js 的异步
> Js 是一门单线程语言，因为他运行在浏览器的渲染主线程中，
> 由于渲染主线程任务繁重，同步处理会不可避免的导致堵塞，造成卡顿
> 使用异步可以极大程度的解放浏览器，保证浏览器永不阻塞

### Js 怎么阻塞线程？
一个函数
Fu{
     改变标签字符；
     死循环 30 秒；
}

当 fu 触发后，你会发现页面卡死了 30 秒才渲染

这是因为新触发的渲染事件被堵在 fu 函数后面

### 任务有优先级吗？
没有

根据 w 3 c 的最新解释，每个任务有一个任务类型

同一个类型的任务必须放在一个队列里
不同类型的任务分属不同队列
在一次事件循环中浏览器按照策略从不同队列取任务 

必须有一个微队列，其中的任务优先于所有任务

延时队列【中】
交互队列【高】
微队列【最高】
